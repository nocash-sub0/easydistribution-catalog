# Catalog: каталог поставщика с разными ценами для каждого клиента

Мой кусок проекта EasyDistribution. Поставщик ведёт каталог товаров, и один и тот же товар стоит по-разному для разных клиентов. Есть админка для поставщика и витрина магазина для покупателей.

**Сайт:** https://easydistribution-catalog.vercel.app
**API:** https://easydistribution-catalog.onrender.com

Render на бесплатном тарифе засыпает, если сайтом долго не пользуются. Первый запрос после паузы может грузиться до минуты, потом всё работает быстро.

## Как запустить у себя

```bash
git clone https://github.com/nocash-sub0/easydistribution-catalog.git && cd easydistribution-catalog
npm install
npm run dev
```

Откроется http://localhost:5173. Никаких паролей и `.env` не надо, нужен только Node.js 20+. Фронтенд у вас запускается локально, а данные берёт с моего бэкенда на Render, там же лежат все ключи.

Висит первая загрузка? Это просыпается Render. Минуту подождать и обновить страницу.

### Демо-доступ

| Роль | Логин | Пароль |
|---|---|---|
| SRL Alfa, клиент VIP | `alfa` | `r9vvQwK442` |
| SRL Beta, клиент Mic | `beta` | `UYVbZwx7YS` |
| SRL Gamma, без своего прайс-листа | `gamma` | `7n6cZCuKa7` |
| Админ | передаю преподавателю отдельно | |

Самое главное из задания проверяется так: зайти по очереди под alfa, beta и gamma и посмотреть на один и тот же товар. Цена у всех троих разная. У gamma своего листа нет, и он видит цены по умолчанию, как гость.

Оплату можно проверить тестовой картой Stripe: `4242 4242 4242 4242`, дата любая из будущего, CVC любой. Деньги не списываются.

### Полный запуск со своим бэкендом (необязательно)

Это если хочется поднять и бэкенд у себя. Понадобится своя база MySQL: копируете `backend/.env.example` в `backend/.env`, вписываете данные и запускаете:

```bash
npm run db:init
npm run dev:full
```

API встанет на http://localhost:3000, и сайт переключится на него.

`db:init` заливает таблицы и тестовые товары только в пустую базу. Если товары там уже есть, он ничего не трогает. Пароли клиентов у вас получатся свои, не те, что в таблице выше: `db:init` придумывает их заново и выводит в конце.

## Что есть на сайте

**Каталог (админ)**
- таблица на 800+ товаров, не тормозит за счёт виртуализации; цену можно поменять прямо в ячейке
- фильтр по категории и поиск, который ждёт, пока допечатаешь (debounce)
- форма товара: код, название, категория, базовая единица, единица продажи с коэффициентом (bax = 24 buc), ставка TVA
- импорт CSV: сначала предпросмотр, потом отчёт по строкам вида «строка 14: неверная ставка TVA». Кривые строки пропускаются, остальные импортируются
- состояния экрана: скелетон при загрузке, пустой каталог, ошибка с кнопкой «Повторить»

**Списки цен (админ)**
- создать, переименовать, удалить прайс-лист
- привязать к листу клиентов, с поиском и выбором сразу нескольких
- сравнить лист с базовым, отличия подсвечены
- скидка в % на всю категорию, с предпросмотром до сохранения
- цены в MDL, переключатель «с TVA / без TVA»

**Витрина**
- каталог видят все, а цены зависят от того, кто вошёл
- вход по логину и паролю, регистрация по почте или через Google, сброс пароля по почте
- корзина и оплата картой через Stripe (тестовый режим, деньги не списываются)
- профиль: история заказов, отмена заказа, привязанная карта, тема и язык
- акции на всех клиентов сразу или на одного
- русский, румынский и английский, переводятся и интерфейс, и товары

## Как считаются цены

- В базе: поставщик, товар, единица измерения, прайс-лист, позиция в листе и привязка листа к клиенту.
- `GET /catalog?clientId=` берёт цену из листа клиента. Нет у клиента своего листа или нет в нём этого товара, тогда цена идёт из листа по умолчанию.
- Перевод штук в коробки (buc → bax) и TVA считаются в одной функции на сервере, а не в каждом запросе заново.

## Тесты

```bash
cd backend && npm test
```

Тесты гоняются на отдельной базе `catalog_test`, которую каждый раз создают заново, так что рабочие данные они не портят. Без заполненного `backend/.env` не запустятся, тут то же, что в полном запуске.
